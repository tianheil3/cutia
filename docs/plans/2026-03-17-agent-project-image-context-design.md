# TIA-50 Agent 读取项目图片素材设计

## 背景

当前网页里的 Agent 已经能读取项目名、时间线结构和素材元数据，也能通过工具列出媒体资源，但它看不到图片素材本身的内容。对用户来说，这意味着 Agent 无法回答“这张图里是什么”“用当前项目里的图做参考继续生成”这类问题，只能依赖文件名和尺寸猜测。

工单目标是把网页里的 AI 扩展成“能读取当前项目素材内容”的版本，票据里特别指出以图片素材为主，因此本次范围聚焦项目内图片资源，不扩展到视频逐帧理解或音频语义识别。

## 约束

- 继续复用浏览器端现有的 OpenAI-compatible Agent 配置，不新增服务端凭据通道。
- 不把所有图片内容自动塞进系统提示词，避免每轮对话都重复消耗视觉 token。
- 不改变现有项目素材存储模型，直接复用 `MediaAsset.file`。
- 真实验收必须经过真实 API，而不是纯 mock。

## 方案比较

### 方案 A：新增按需图片分析工具

给 Agent 新增一个图片理解工具，按需读取当前项目中的图片素材，把图片转成 data URL 后调用现有 vision 接口返回描述。

优点：

- 改动集中在 Agent 工具层，和现有架构最贴合。
- 只有在模型确实需要看图时才消耗视觉调用。
- 可以把用户问题作为分析焦点传给 vision，提高结果相关性。

缺点：

- 模型通常需要先 `list_media_assets` 再调用分析工具，链路会多一次 tool round。

### 方案 B：在系统提示词中预注入全部图片内容

每轮构造系统提示词时自动分析全部项目图片，并把描述写入 prompt。

优点：

- 模型首轮回答就拥有图片语义。

缺点：

- 成本和延迟最高。
- 素材多时上下文迅速膨胀。
- 每轮都重复分析，和现有 Agent 按需工具调用模式不一致。

### 方案 C：先做离线缓存，再把缓存暴露给 Agent

上传图片后预生成摘要并持久化，Agent 只读取缓存。

优点：

- 二次使用成本低。

缺点：

- 需要新增缓存生命周期、迁移、失效策略和 UI 联动。
- 对当前工单来说明显超出必要范围。

## 选型

采用方案 A。

理由：它直接建立“Agent 可以读取当前项目图片内容”的最小可用闭环，同时复用现有 `vision.ts` 能力，不引入新的后端协议和持久化负担。后续如果证明用户会高频复用同一批图，再在此基础上补缓存会更稳妥。

## 详细设计

### 1. 新增图片理解工具

新增 `analyze_project_images` 工具，行为如下：

- 输入：
  - `mediaIds?: string[]`，可选，指定要读取的图片素材 ID。
  - `question?: string`，可选，把用户关注点拼进视觉提示词。
- 输出：
  - 返回成功/失败消息。
  - 成功时返回每张图片的 `id`、`name`、`width`、`height` 和 `analysis`。

执行规则：

- 仅处理当前项目中的 `image` 类型素材。
- 未传 `mediaIds` 时：
  - 如果项目里没有图片，直接返回可理解的失败信息。
  - 如果图片数量较多，只分析前几张并在结果中明确截断，避免单次工具调用过重。
- 传入 `mediaIds` 时只分析匹配到的图片，并在结果里保留原素材顺序。

### 2. 复用现有视觉链路

工具内部复用：

- `MediaAsset.file` 读取项目内原始图片。
- `blobToDataUrl` 把图片转成 data URL。
- `analyzeImageWithVision` 通过当前 Agent 设置里的 `baseUrl / apiKey / model` 调用真实视觉模型。

新增一个面向“项目图片阅读”的默认分析提示词，覆盖这些信息：

- 主要主体和场景
- 构图与镜头感
- 明显文字或 UI
- 视觉风格、色彩和氛围
- 对视频编辑/继续生成最有用的线索

如果用户附带 `question`，则把它追加到默认提示词末尾，作为聚焦分析项。

### 3. 更新系统提示词

在 Agent 系统提示词里新增两类信息：

- 能力说明：Agent 可以读取当前项目的图片素材内容。
- 调用指导：当用户询问项目图片里有什么、要基于现有图片继续生成、或要理解画面元素时，应先 `list_media_assets`，再调用 `analyze_project_images`。

这样模型不会只停留在素材文件名层面。

### 4. 可测试性设计

为避免工具实现完全依赖 `EditorCore` 单例和真实视觉 API，本次会把媒体筛选与视觉调用封装成可注入依赖的工厂函数，便于：

- 单元测试里传入假编辑器和假 vision 函数。
- 真实 API 验证时复用同一工具逻辑，只替换 data URL 转换实现。

### 5. 失败与退化路径

- 没有活动项目或没有图片素材时，返回明确失败信息，不抛未捕获异常。
- 指定的 `mediaIds` 不存在或不是图片时，返回可定位问题的消息。
- 视觉接口失败时，透传可读错误信息，方便用户检查 Agent API 配置。

## 测试与验证

### 自动化

- 为新工具补 `bun test` 单测，覆盖：
  - 无图片素材时的失败路径
  - 按 `mediaIds` 过滤分析目标
  - `question` 会被拼进视觉提示词
  - 返回结果结构稳定

### 真实 API

新增一个轻量验证脚本：

- 使用仓库内现成图片样本构造项目图片素材。
- 注入环境里的 `API_BASE_URL / API_KEY / API_MODEL`。
- 直接调用新工具，验证返回的分析结果非空且包含图片内容描述。

## 非目标

- 不做视频内容理解。
- 不做图片摘要缓存或持久化。
- 不改 Agent UI 交互形态，只增强其能力与提示词。
